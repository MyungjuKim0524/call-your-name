## 1. 개발 배경과 목표

1차 서비스는 음악에서 영감을 받은 개인화 위로 비주얼 노벨이다. 이름 입력, 기존 세 가지 고민 분기, 6종 동물 캐릭터, 응원 포토카드, 익명 방명록을 구현했다. 현재 구조는 이야기의 끝이 곧 서비스 이용의 끝이 되기 쉽고, 직접 조작하는 경험이 제한적이다.

**서비스 정의:** 내 이름을 불러주는 동물 친구들과 위로 이야기를 직접 경험하고, 나만의 오두막에서 쉬며, 밤빛 해변에서 마음을 나누고, 나만의 콘서트를 연출하는 감성 인터랙티브 콘텐츠 서비스.

| 목표 | 방향 |
|---|---|
| 초기 취지 유지 | 기존 고민과 캐릭터, 직접 작성한 위로 대사를 보존한다. |
| 스트레스 해소 목적 강화 | 고민을 상징하는 오브젝트와 조작을 서사에 결합하여 시청각적 만족감과 위로를 함께 제공한다. |
| 재미와 체류 경험 | 자유 탐색, 음악 공연 연출, 꾸미기, 편지 발견을 통해 자발적으로 머무르거나 다시 찾아올 이유를 만든다. |
| 감성 | 자연스러운 공간 변화, 작은 행동에 대한 섬세한 시청각 반응, 따뜻한 캐릭터 교감. |
| 확장성 | 3차에서 글로벌 콘텐츠·팬 참여 기능을 추가할 수 있도록 최소한의 공통 기술 기반을 정비한다. |

정서적 휴식과 기분 전환을 위한 콘텐츠이며 진단·치료·스트레스 감소 효과를 보장하지 않는다. 동물의 숲의 느긋한 생활형 인터랙션을 참고하되 캐릭터, UI, 음악 등은 자체 제작 또는 적법한 사용 권한을 확보한 자산을 사용한다.

## 2. 서비스 구조와 공간별 역할

| 공간/콘텐츠 | 역할 | 주요 이용 경험 |
|---|---|---|
| 나만의 오두막 | 개인 공간 및 허브 | 이름을 불러주는 친구, 위로 이야기 진입, 옷장, 기본 환경음, 자유 휴식 |
| 인터랙티브 위로 스토리 | 서비스의 핵심 콘텐츠 | 기존 A/B/C 고민에 맞춘 대화와 상징적 감각 인터랙션 |
| 밤빛 해변 | 간접적인 사용자 교류 공간 | 파도·밀물/썰물 연출, 병편지 작성·띄우기·발견, 별빛 불꽃놀이 |
| 별빛 콘서트 | 능동적 놀이·기분 전환 | 음악 선택, 출연진·대형·의상 설정, 무대 조명·효과·안무 연출 |
| 응원·공연 포토카드 | 경험의 기념과 공유 | 기존 Canvas 기반 이미지 생성, 개인화된 장면 저장·선택적 공유 |

별빛 콘서트는 밤빛 해변 인근의 작은 무대라는 콘셉트를 권장한다. 별도 3D 맵이나 캐릭터 이동 엔진은 구축하지 않고 기존 2D/SVG 기반 화면 간 전환으로 표현한다. 위치 및 명칭은 화면 설계 단계에서 조정 가능하다.

### 이용 흐름

- 첫 방문: 기존 오프닝 및 이름 입력 → 오두막 입장 → 기존 고민 선택 또는 자유 탐색.
- 위로 이야기: A/B/C 선택 → 캐릭터 대화 → 상징적 조작 → 감각 피드백 → 위로 대사 → 선택적 포토카드 → 오두막 복귀.
- 자유 탐색: 오두막 ↔ 밤빛 해변 ↔ 콘서트. 언제든 활동을 선택·중단하고 돌아올 수 있다.
- 재방문: 선택적으로 로컬에 저장한 이름과 설정을 재사용하고 오두막부터 시작. 기존 이야기는 언제든 다시 이용 가능.

## 4. 핵심 콘텐츠 상세 기획

### 4.1. 나만의 오두막

- 사용자 각자의 집이라는 콘셉트의 개인 공간. 다른 사용자의 집 방문이나 실시간 접속 공유는 제외한다.
- 6종 동물 친구와 기존 캐릭터 디자인을 유지한다. 친구를 선택하거나 안내 대사를 통해 위로 스토리를 시작할 수 있다.
- 옷장, 해변, 콘서트 등의 진입점을 제공한다. 상호작용 가능한 사물의 위치·표현은 화면 설계에서 확정한다.
- 개인 설정은 기본적으로 브라우저 로컬에 저장한다. 계정이나 서버 기반 개인 월드 저장은 필수 요구가 아니다.
- 모닥불·기존 BGM을 기본 환경음으로 유지한다. 사용자가 재생을 선택하고 음소거할 수 있다.

### 4.2. 메타포 기반 인터랙티브 위로 스토리 (핵심)

고민을 시각적으로 형상화하고, 캐릭터의 제안에 따라 사용자가 오브젝트를 직접 변화시키며, 그 경험과 연결된 위로 메시지를 받는다. 별도의 미니게임 목록을 핵심으로 삼지 않는다.

| 기존 분기 | 기존 출연 캐릭터 | 기존 메시지 방향 | 인터랙션 후보 (미확정) |
|---|---|---|---|
| A: 진로·역량 불안 | 아기 늑대 | 자신의 가능성과 도전할 용기 | 걱정 풍선 터치로 터뜨리기 → 색색의 별빛·경쾌한 소리 |
| B: 미래 불안·자신감 저하 | 흰색 족제비, 금색 햄스터 | 불확실성 속에서 자신을 믿기 | 구름을 밀어 밤하늘의 별 발견 → 잔잔한 빛·소리 |
| C: 울적한 감정 | 아기 리트리버, 기니피그 | 억지로 행복해지지 않아도 됨 | 김 서린 창문 닦기 또는 차 우리기 → 빗소리·따뜻한 조명 |

- 각 분기에 하나의 대표 인터랙션을 먼저 구현한다. 위 후보는 설계 예시이며 실제 대사·활동은 스토리보드 승인 후 확정한다.
- 대화 → 오브젝트 등장 → 조작 → 감각 피드백 → 위로의 연결을 유지한다. 풍선은 화면 터치 등 가상 조작으로 구현한다.
- 기존 직접 작성한 대사를 최대한 보존하고 필요한 연결 대사만 추가한다. 고민을 하찮게 여기거나 미래 결과를 보장하는 표현은 피한다.
- 시간 제한, 점수, 실패 판정, 필수 반복은 없다. 스킵과 중단을 지원하며 조작하지 않고 위로 대사를 읽는 것도 가능하다.
- 고민의 종류를 대량 추가하지 않는다. 장기적으로 한 카테고리에 여러 에피소드를 연결할 수 있는 식별자 구조만 마련한다.

### 4.3. 밤빛 해변·별빛 병편지

- 밤바다와 가상의 밀물·썰물로 편지가 물결에 따라 밀려오는 공간을 연출한다. 실제 조석 API와 해류 물리 시뮬레이션은 제외한다.
- 편지 작성 또는 준비 문구 선택 → 병에 담기 → 화면을 밀거나 버튼으로 바다에 띄우기 → 등록 성공 시 병이 멀어지고 작은 별빛 불꽃놀이 → 바다 감상 또는 다른 편지 발견.
- 불꽃놀이는 점수·보상 재화가 아니라 행동 완료에 대한 감성적 피드백이다. 음량/모션 설정을 따른다.
- 방문자는 공개 승인된 익명 응원 편지를 발견해 읽는다. 실제 조석 시간까지 기다리거나 편지를 보내야만 읽을 수 있는 조건은 없다.
- 편지는 여러 사람이 읽을 수 있다. 직접 답장, 사용자 검색·프로필, 외부 연락 연결, 비공개 고민 교환은 제공하지 않는다.
- 자유 입력 공개는 운영자 승인·신고·삭제·서버 검증이 갖춰졌을 때만 허용한다. 검수 운영이 어려우면 준비된 응원 문구만 선택할 수 있는 안전한 축소 버전을 적용한다.
- 기존 방명록은 무단 재공개하지 않는다. 백업 및 기존 공개 범위 검토 후 이관 여부를 결정한다.

### 4.4. 별빛 콘서트 — 나만의 콘서트 연출하기

**핵심 역할:** 사용자는 무대 감독이자 관객으로서 음악과 동물 친구들의 공연을 자유롭게 꾸민다. 독립 밴드 게임·리듬게임·뮤직비디오 제작 기능은 만들지 않는다.

| 단계 | 경험 |
|---|---|
| 공연 준비 | 음악 선택, 기존 동물 친구 출연진과 센터/대형 선택, 기본 무대 선택 |
| 공연 중 | 음악에 맞춘 기본 춤 동작, 조명 색상, 별빛·색종이·비눗방울·불꽃놀이 효과, 대형 또는 안무 프리셋 변경 |
| 공연 종료 | 하이라이트 장면 감상, 다시 공연, 오두막 복귀, 선택적 공연 포토카드(P1) |

- 최초 2~3곡 목표. 자체 합성 또는 공개 웹 서비스 재생·시각 동기화·배포 권한을 확인한 음원만 사용한다. Gemini 등 생성 음원은 해당 이용 조건을 확인한 경우만 채택한다. 무료 생성이 곧 재배포 허용을 의미하지 않는다.
- 실제 K-pop 음원은 권리 확보 전 사용하지 않는다. 외부 스트리밍 서비스 음원을 무단 추출하거나 게임 연출에 연결하지 않는다.
- 음악 재생 위치와 BPM/박자 데이터에 맞춰 기본 캐릭터 움직임을 동기화한다. 실제 정교한 안무 자동 생성이나 음원 분석 모델은 필수 범위가 아니다.
- 사용자는 원하는 타이밍에 무대 효과를 조작한다. 정확도 점수, 랭킹, 실패, 강제 반복 없음.
- 최소 범위는 무대 1개, 기본 대형 2종, 기본 춤 프리셋, 조명 색상 및 효과 2종 이상. 수치와 리소스 개수는 구현을 위한 제안 기준이다.
- 의상 선택, 응원봉 커스텀, 공연 프리셋 저장 및 공연 포토카드는 P1. 라이브 멀티플레이, 영상 저장, 시즌 공연은 3차 이후.

### 4.5. 캐릭터 옷장·포토카드

- 기존 SVG 캐릭터에 자체 디자인 의상·소품을 레이어로 적용. 소수 아이템부터 시작하고 캐릭터별 호환성을 검증한다.
- 오두막과 콘서트에서 동일 설정을 재사용한다. 유료 구매·확률형 획득·코인·출석 잠금은 제외한다.
- 기존 응원 포토카드 생성과 다운로드는 유지한다. P1에서 공연 장면, 의상·배경을 반영하고 Web Share API를 지원할 경우 공유한다.
- 이름이나 고민을 제외한 공유용 카드 옵션을 제공한다. 개인화 이미지의 서버 업로드는 기본 범위가 아니다.

| Tone.js / Web Audio API | 기존 오디오 기반 활용 및 음악-연출 동기화 |
| Spring Boot·Spring Data JPA·Spring Security | 병편지의 신뢰 가능한 서버 검증, 운영 API, 3차 확장 대비 |
| 기존 Supabase PostgreSQL·Flyway | 운영 데이터 보존 우선, 관계형 제약과 마이그레이션 |
| LocalStorage | 이름(선택), 의상·음량·프리셋 등 기기 내 설정 |
| JUnit·PostgreSQL 통합 테스트·Playwright | 서버 정책, 기존 시나리오, 모바일/PC 회귀 검증 |
| Vercel + 무료 백엔드 환경 | 기존 호스팅 유지. 무료 서버의 실제 가용성은 착수 전 검증 |

백엔드는 병편지 중심으로 한정하며 모든 감각 조작이나 공연 효과를 서버로 보내지 않는다. 기존 공개 쓰기 권한은 안전한 서버 전환 후 제거한다. 무료 백엔드 배포가 불가능하면 로컬로 구현을 검증하고 공개 서비스에는 안전한 준비 문구/읽기 전용 대안을 적용한다.

## 6. 로드맵 및 범위 통제

| Phase | 주요 개발 | 완료 기준 | 예상 집중 작업일 |
|---|---|---|---|
| 0 | 기준선·스토리보드·자산 권리·DB 정책 | 기존 3개 경로 기준선 및 P0 확정 | 1~2 |
| 1 | 모듈화·오두막 허브·FSM 확장 | 기존 흐름 유지, 진입·복귀·스킵 | 2~4 |
| 2 | A/B/C 인터랙티브 위로 스토리 | 분기별 대표 활동 및 감각 피드백 | 3~5 |
| 3 | 병편지 서버·해변 연출 | 승인/삭제/신고 정책, 등록 성공 피드백 | 4~6 |
| 4 | 콘서트 | 권리 확인 음원, 음악-연출 동기화, 무대 조작 | 3~5 |
| 5 | 통합 테스트·배포·문서화 | P0 테스트 통과, 실제 배포 가능 범위 기록 | 2~3 |
| 6 | 옷장·공연 카드·공유 등 P1 | 핵심 기능 안정화 후 선별 | 2~4 |

P0만 약 15~25 집중 작업일로 추정한다. 2주 안에 전부 구현하기 어렵다면 대표 활동의 복잡도, 콘서트 자산 수, 병편지 입력 방식부터 축소한다. 기존 세 분기와 핵심 보호 정책은 유지한다. Spring 학습 및 콘텐츠 제작 시간에 따라 일정 연장이 필요할 수 있다.

## 7. 성공 기준

- 기존 3개 이야기와 포토카드가 정상 동작하고 모든 활동에서 오두막으로 복귀할 수 있다.
- 각 고민별 조작이 위로 메시지와 의미상 연결되며 사용자가 조작을 건너뛸 수 있다.
- 병편지 등록·발견·실패 처리와 공개 정책이 서버에서 일관되게 동작한다.
- 콘서트에서 음악 재생과 캐릭터 기본 안무가 연동되고 사용자가 무대 연출을 자유롭게 변경할 수 있다.
- 소규모 자발적 사용성 피드백으로 재미, 조작 편의, 콘텐츠 선호, 재이용 의향을 확인한다. 이용 시간 자체를 극대화하거나 치료 효과를 주장하지 않는다.
