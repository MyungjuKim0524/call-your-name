# 네 이름을 불러줄게! v2.0 — PRD (Product Requirements Document)

- 작성 기준: 2026-11-29 / 구현 전 요구사항 기준안
- 제품 기획: [PLANNING_V2.md](PLANNING_V2.md)
- 기존 서비스: https://call-your-name.vercel.app/ / https://github.com/MyungjuKim0524/call-your-name
- P0 출시 필수, P1 권장, P2 선택. 아래 수치·API·UI는 검증 가능한 구현 기준으로 제안한 초안이며 실제 구현 완료를 뜻하지 않는다.

## 1. 목표 및 비목표

기존 이름 개인화와 세 가지 위로 분기를 유지하면서 사용자 조작이 이야기의 일부가 되도록 개선한다. 개인 오두막 허브, 익명 병편지 해변, 개인 콘서트 연출을 연결해 선택의 자유와 반복 가능한 즐거움을 제공한다. 임상 효과, 사용 시간 극대화, 팬덤 경쟁, 3차 플랫폼 기능은 목표가 아니다. 추가 유료 서비스 사용 없이 구현하는 것을 원칙으로 한다.

## 2. 사용자 및 주요 시나리오

주 대상은 기존 기획의 20~30대 사용자와 팬 콘텐츠에 관심 있는 방문자다. 공개 서비스 특성상 다양한 연령대의 접근을 고려한다. 계정 없이 시작할 수 있으며 사용자의 고민이나 신원을 수집할 필요가 없다.

| ID | 사용자 시나리오 | 기대 결과 |
|---|---|---|
| US01 | 위로가 필요한 방문자가 기존 고민을 선택한다. | 캐릭터와 대화·조작·위로를 경험한다. |
| US02 | 이야기를 이미 본 방문자가 다시 찾아온다. | 이름 입력 반복 없이(저장 동의 시) 원하는 활동을 선택한다. |
| US03 | 응원을 전하고 싶은 방문자가 해변을 찾는다. | 편지를 보내고 등록 완료 연출을 본다. |
| US04 | 다른 여행자의 응원을 발견하고 싶다. | 승인된 병편지를 읽을 수 있다. |
| US05 | 기분 전환을 위해 공연을 즐기고 싶다. | 선곡·출연진·무대 효과를 자유롭게 조작한다. |
| US06 | 경험을 간직하거나 공유하고 싶다. | 포토카드를 저장하고 지원 환경에서 공유한다. |
| US07 | 활동을 그만두거나 사운드·모션을 줄이고 싶다. | 강제 진행 없이 중단·복귀하고 설정을 적용할 수 있다. |

#### 병편지 상태 및 정책

- `PENDING`(검수 대기), `PUBLISHED`(공개), `HIDDEN`(숨김), `REJECTED`(반려). 삭제는 공개 조회에서 즉시 제외하고 보존 정책에 따라 본문 제거.
- 준비 문구는 서버에서 승인 목록을 관리한다. 자유 입력을 활성화하는 경우 길이(제안 2~60 Unicode 문자, 공백 제거 후), 허용 문자 및 안전 정책을 서버와 DB에서 일치시킨다. Trie는 보조 필터이며 운영자 검수를 대신하지 않는다.
- 편지 작성 성공 시 응답에 상태를 명시한다. 사용자에게 실제 다른 사람에게 전달되었다고 보장하지 않는다.
- 직접 답장, 사용자 간 계정 연결, 연락처 노출 및 개인 고민 교환은 제외한다.
- 운영자가 검수할 수 없거나 안전한 무료 배포가 불가능한 경우 준비 문구 기반의 제한된 기능 또는 읽기 전용 모드로 출시한다. 이를 정상적인 자유 입력 등록처럼 표시하지 않는다.

#### 음악 재생 및 동기화 원칙

- 자체 합성 음원 또는 명시적으로 사용 권리를 확인한 파일을 사용한다. Gemini 생성 음원은 서비스 삽입, 재배포, 시각 콘텐츠 동기화 조건을 확인한 뒤 채택한다. 실제 K-pop은 허가 전 사용 금지.
- 트랙 메타데이터에 `trackId`, `title`, `assetRef`, `duration`, `bpm` 또는 `beatMarkers`, `beatOffset`, `rightsStatus`를 둔다. BPM과 오프셋은 실제 트랙에 맞게 검증한다.
- 재생 시간은 오디오 재생 위치를 기준으로 삼는다. 단순 setInterval 누적값을 기준으로 하지 않는다. 화면 비활성화, 재개, 곡 변경 시 동기화를 재계산한다.
- 효과는 클라이언트에서 실행한다. 정교한 안무 생성, 음원 분리, 공연 영상 인코딩 및 실시간 멀티플레이는 제외한다.
- 구체적인 동기화 허용 오차는 대상 브라우저의 기준선 측정 후 확정한다. 테스트에서 실제 오차와 측정 방법을 기록한다.

## 5. 데이터·시스템 요구사항

### 5.1. 클라이언트 구조

기존 `currentStep`, `SCENARIO_GRAPH`, `renderFSMNode()`, `PHOTOCARD_ROUTES`, `GuestbookRepository`, Tone.js 자산을 기준으로 점진적으로 모듈화한다. 새로 코드를 전면 재작성하지 않는다.

```text
frontend/           # Vercel 배포 (Root Directory: frontend)
  index.html
  src/
    core/           # scene engine, navigation, state
    content/        # characters, scenarios, tracks, presets
    interactions/   # 고민별 조작 모듈
    spaces/         # cabin, beach
    features/       # bottle-letter, concert, wardrobe, photocard
    effects/        # particles, waves, fireworks
    audio/          # playback, beat timeline, settings
  assets/           # 서비스 런타임 자산 (이미지·음원)
  tests/            # Playwright E2E
backend/            # Spring Boot API (Gradle, JUnit, Flyway 마이그레이션)
docs/               # 문서 (docs/assets/는 문서용 이미지)
```

- 루트의 `index.html`은 Phase 1 모듈화 착수 시 `frontend/`로 옮기고, 같은 시점에 Vercel Root Directory를 `frontend`로 변경한다. ([D-002](../DECISIONS.md))

- 콘텐츠 식별자: `categoryId`, `episodeId`, `sceneId`, `characterId`, `interactionId`, `trackId`, `presetId`.
- 시나리오 노드는 `type`, `next`, 선택적 `interactionId`, `onSkip`, `textKey` 등을 가진다. 스킵 경로와 다음 노드의 참조 유효성을 검증한다.
- 상호작용 모듈은 초기화, 시작, 중단, 정리의 공통 생명주기를 갖는다. 화면 이동 시 리스너, 애니메이션 프레임, 오디오 및 타이머를 해제한다.
- 이름과 고민 선택은 클라이언트에서 처리하며 서버 로그·분석 이벤트에 포함하지 않는다. 개인 설정은 선택적 LocalStorage 및 버전/초기화 관리로 처리한다.

### 5.2. 서버·DB (병편지 중심)

Spring Boot, Spring Data JPA, Spring Security, PostgreSQL(기존 Supabase 우선), Flyway를 권장한다. 다른 기능의 서버 저장은 필수 요구가 아니다.

| 테이블/데이터 | 주요 필드 | 제약 |
|---|---|---|
| `bottle_letters` | id, message 또는 template_id, status, created_at, deletion_token_hash, request_id | PK, 상태 CHECK, 길이 CHECK, request_id UNIQUE, 본문/템플릿 유효성 |
| `letter_reports` | id, letter_id, reason_code, created_at, status | FK, 허용된 신고 사유, 처리 상태 |
| `moderation_actions` | id, letter_id, action, reason_code, created_at | FK, 관리자 기록; 원문·토큰 미기록 |
| `letter_templates` (DB 또는 서버 리소스) | template_id, message, active | 승인된 준비 문구만 사용 |

- 기존 운영 `guestbook` 데이터를 먼저 백업한다. 이관은 원래 공개 범위와 삭제 요청을 검토한 뒤 결정한다. 운영에서 파괴적 초기화 SQL 실행 금지.
- 중복 등록 방지: 클라이언트 요청 ID 및 DB UNIQUE 기반 멱등 처리. 재시도 시 동일 요청의 접수 상태를 반환하고 새 편지를 만들지 않는다. 동일 ID로 다른 요청을 보내면 충돌 처리한다.
- 삭제 토큰은 추측하기 어려운 값으로 발급, 서버는 해시 저장, 클라이언트는 사용자가 삭제할 수 있도록 안전하게 제공한다. 재시도 응답은 토큰 원문 노출을 방지하도록 구현하며 토큰을 잃은 사용자의 운영자 삭제 요청 경로도 마련한다.
- 등록 제한은 서버에서 적용하고 단일 인스턴스 한계를 문서화한다. 개인정보 장기 추적 없이 서비스 전체 저장량 상한 등 보호책도 설정한다.
- 개발/테스트/운영 DB 분리, 최소 권한 DB 계정, 직접 공개 쓰기 차단. 실제 운영 권한은 배포 전 확인한다.

### 5.3. API 계약 초안

| Method | Endpoint | 계약 요약 |
|---|---|---|
| GET | `/api/v1/bottle-letters/discover` | 공개 승인 편지 또는 기본 문구 제공; 내부 메타데이터 제외 |
| GET | `/api/v1/bottle-letters/templates` | 활성 준비 문구 조회 |
| POST | `/api/v1/bottle-letters` | requestId + templateId 또는 허용된 message; id/status 반환 |
| POST | `/api/v1/bottle-letters/{id}/reports` | 허용 사유 코드로 신고 접수 |
| DELETE | `/api/v1/bottle-letters/{id}` | 작성자 삭제 권한 검증 후 공개에서 제외 |
| GET | `/api/v1/admin/bottle-letters` | 인증된 관리자의 검수 대상 조회 |
| PATCH | `/api/v1/admin/bottle-letters/{id}/status` | 관리자 승인/숨김/반려 |
| GET | `/api/health` | 최소 상태 응답, 민감 설정 미노출 |

정상 응답, 입력 오류 400, 권한 오류 401/403, 없는 자원 404, 요청 충돌 409, 제한 429, 장애 5xx를 명확히 구분한다. 관리자 인증·CSRF(쿠키 기반일 경우)·CORS 정책을 구현 방식에 맞게 검증한다. 구체 DTO와 상태코드는 OpenAPI 작성 시 확정한다.

## 9. 미확정 사항과 변경 통제

- A/B/C 인터랙션 및 신규 대사, 콘서트 곡·안무·무대·효과 자산, 세부 화면 디자인은 승인 후 확정한다. 후보를 확정된 요구사항으로 오인하지 않는다.
- 병편지 자유 입력 공개 여부, 보존·삭제 정책 세부 기간, 기존 방명록 이관 여부, 무료 백엔드 호스팅 가용성은 착수 전 확인한다.
- 3차 후보(SSE·Redis·실시간 공동 공연, 시즌 이벤트, 글로벌 콘텐츠 운영·AI 현지화·분석)는 본 PRD 구현 범위가 아니다.
- 개발 에이전트는 P0 변경이나 추가 의존성, 유료 서비스 사용, 기존 데이터 변경을 임의로 확정하지 않는다. 변경 사유와 대안을 기록하고 승인 후 반영한다.
- 본 PRD는 이전 확인 코드와 기획 대화를 근거로 작성했으며 실제 운영 환경이나 최신 저장소 상태를 새로 감사하지 않았다. 코드 수정 및 배포는 수행하지 않았다.
