## TS-01. 캐릭터가 거대해지고 서로 겹침

- **증상**: 오두막 장면에서 흰색 족제비가 비정상적으로 크게 표시되고, 캐릭터들이 서로 겹쳐 가려짐
- **원인**: AI가 Tailwind CSS에 존재하지 않는 크기 클래스(`w-25`, `w-26`, `w-30`)를 생성했습니다. 이 클래스는 아무 스타일도 적용하지 않기 때문에, 크기 제한이 사라진 SVG가 영역을 가득 채웠습니다.
- **해결**
  - 모든 캐릭터 크기를 Tailwind 표준 클래스(`w-20 h-20 sm:w-24 sm:h-24`)로 통일
  - 방석 위에 앉아 있는 배치로 바꾸고, 캐릭터 간 간격을 고정
- **검증**: 수정된 화면을 직접 실행해 확인

## TS-02. 방명록 저장 실패

- **증상**: 방명록을 작성하면 “서버 저장 중 오류가 발생했어요. 테이블 설정을 확인해주세요.”라는 메시지가 뜨고 저장되지 않음
- **1차 조치 (해결되지 않음)**
  - AI는 `guestbook` 테이블이 이전 버전으로 남아 있거나 RLS의 INSERT 정책이 빠졌을 가능성을 진단했습니다. 테이블 생성 때 `ERROR: 42P07: relation "guestbook" already exists`가 발생했기 때문입니다.
  - 테이블을 다시 만들고 RLS 정책과 권한을 재설정하는 SQL을 실행했지만, 같은 오류가 반복됐습니다.
- **원인**: Supabase URL이 `https://<project>.supabase.co/rest/v1/`로 설정되어 있었습니다. Supabase JS 클라이언트는 기본 URL 뒤에 API 경로를 스스로 붙이므로, 기본 URL만 넣어야 합니다.
- **원인 파악이 늦어진 이유**: 오류 메시지가 실제 DB 오류를 가리고 “테이블 설정을 확인하라”고만 안내해, 테이블과 권한 쪽을 먼저 의심하게 됐습니다.
- **해결** (`f283ff8`)

  ```diff
  - url: "https://<project>.supabase.co/rest/v1/",
  + url: "https://<project>.supabase.co",
  ```

  ```diff
  - throw new Error("서버 저장 중 오류가 발생했어요. 테이블 설정을 확인해주세요.");
  + throw new Error(`DB 저장 오류 (${error.code || "ERR"}): ${error.message}`);
  ```

  - 오류 코드와 사유가 화면에 그대로 보이도록 바꿔, 이후 문제가 생기면 원인을 바로 알 수 있게 함
  - 등록에 성공하면 클라우드 목록을 바로 다시 불러와 화면에 반영
  - 1차 조치에서 정비한 테이블·RLS 구성은 현재 운영 스키마로 유지 ([supabase/schema.sql](../supabase/schema.sql))
- **검증**: 팬 사이트 공유 후 실제 사용자 2명의 방명록 저장 확인

## TS-03. 방명록에 글이 등록되면 기본 메시지가 사라짐

- **증상**: 방명록에 실제 글이 하나라도 등록되면, 캐릭터들이 남긴 기본 응원 메시지가 모두 사라짐
- **원인**: DB에 글이 있으면 DB 글만, 없으면 기본 메시지만 보여주는 양자택일 로직
- **해결** (`3761585`)

  ```diff
  - this.entries = mapped.length > 0 ? mapped : [...this.seedEntries];
  + this.entries = [...mapped, ...this.seedEntries];
  ```

  - 방문자 글은 최신순으로 쌓이고, 기본 메시지는 항상 맨 아래에 남도록 변경
  - 이후 기본 메시지를 6종 캐릭터 모두의 메시지로 확장(`cf7e9c1`)
- **검증**: 글을 등록한 뒤 기본 메시지가 함께 표시되는지 확인

## TS-04. iPhone Safari에서 포토카드 캐릭터가 표시되지 않음

- **증상**: 엔딩에서 응원 포토카드를 저장하면 배경과 문구만 나오고 캐릭터 6종이 보이지 않음 (iPhone Safari)
- **원인**
  - 캐릭터 SVG는 페이지에 한 번만 정의된 크레용 필터(`#crayonBrush`)와 볼터치 그라데이션을 `url(#...)`로 참조합니다.
  - 포토카드를 만들 때 SVG를 Blob 이미지로 분리하면, 그 이미지는 페이지에 접근할 수 없어 참조가 끊깁니다.
  - 끊긴 참조를 처리하는 방식이 브라우저마다 다릅니다.

  | 브라우저 | 끊긴 필터 참조 처리 | 결과 |
  | --- | --- | --- |
  | Chrome | 필터를 무시하고 그림 | 캐릭터는 보이지만 질감과 볼터치가 빠짐 |
  | Safari | 해당 요소를 그리지 않음 | 캐릭터 전체가 사라짐 |

- **분석 과정**
  1. 코드를 읽고 “필터 참조가 끊긴다”는 가설을 세움
  2. 수정 전 코드를 데스크톱 Chrome에서 재현해 보니 **캐릭터가 정상적으로 보임**. 가설과 다른 결과
  3. 같은 결함이 브라우저별로 다르게 나타날 수 있다고 보고, 발견 환경(iPhone Safari)을 확인
  4. 수정본을 Vercel Preview에 배포해 iPhone Safari에서 검증
- **해결** (`c725d90`): 페이지 공용 `<defs>`를 각 캐릭터 SVG 안에 복사해, 다른 문서에 의존하지 않는 SVG로 만든 뒤 이미지로 변환

  ```js
  function serializeCharSVG(id) {
    const sharedDefs = document.getElementById("sharedSvgDefs").outerHTML;
    return getCharSVG(id, { extraClass: "" })
      .replace('class="w-full h-full svg-char "', 'width="220" height="220" xmlns="http://www.w3.org/2000/svg"')
      .replace(/<svg[^>]*>/, (openTag) => openTag + sharedDefs);
  }
  ```

- **검증**

  | 환경 | 수정 전 | 수정 후 |
  | --- | --- | --- |
  | 데스크톱 Chrome | 캐릭터 표시, 질감·볼터치 누락 | 정상 |
  | iPhone Safari (Vercel Preview) | 캐릭터 미표시 | 정상 |

- **교훈**: 개발 환경(데스크톱 Chrome)에서 정상이어도 실제 사용 환경(모바일 Safari)에서는 다를 수 있습니다. 결함은 **발견된 환경에서 재현하고 검증**해야 합니다.

## TS-05. 익명 방명록인데 작성자 이름이 저장되고 조회됨

- **증상**: 방명록은 화면에서 닉네임을 숨기는 익명 방식인데, 실제로는 사용자가 입력한 이름을 DB에 저장하고 있었음
- **영향**
  - 이 서비스는 이름을 불러 주는 콘셉트라, 실명을 입력하는 사용자가 많을 수 있습니다.
  - 조회 정책이 모든 방문자에게 열려 있고, 방명록을 불러올 때 이름도 함께 받아왔습니다. 화면에는 보이지 않아도 브라우저 개발자 도구나 API로 누구나 작성자 이름을 볼 수 있었습니다.
- **원인**: 닉네임 숨김을 화면 표시 단계에서만 처리하고, 저장과 조회 단계는 그대로 둠
- **검토한 대안**

  | 방안 | 내용 | 판단 |
  | --- | --- | --- |
  | A. 이름 수집 중단 | 이름을 저장·조회하지 않음 | **채택**. 익명이라는 기획 의도와 데이터 처리를 일치시키고, 개인정보를 필요한 만큼만 수집 |
  | B. 저장하되 공개 차단 | 이름은 저장하고 방문자의 조회 권한만 제한 | 미채택. 관리자만 이름을 볼 수 있지만, 본인 확인 수단은 되지 못함 |
  | C. 삭제 코드 발급 | 작성자 기기에 삭제 코드를 저장해 본인만 글을 지울 수 있게 함 | 향후 개선 항목. 실제 본인 확인이 가능하지만 구현량이 큼 |

  - “이름이 있어야 나중에 사용자 요청(삭제 등)에 대응할 수 있지 않을까?”도 검토했습니다. 하지만 이름은 사용자가 임의로 입력하는 값이라 중복될 수 있고 다른 사람의 이름을 댈 수도 있어, **본인 확인 수단이 되지 못합니다**. 삭제 요청은 글 내용과 작성 시각으로 글을 찾아 관리자가 처리합니다.
- **해결** (`78b9b6f`)

  ```diff
  - .select("id, author, badge, message, created_at")
  + .select("id, badge, message, created_at")
  ```

  ```diff
    await this.supabase.from("guestbook").insert([
      {
  -     author: safeAuthor,
        badge: chosenBadge,
        message: trimmed
      }
    ]);
  ```

  - 저장하지 않는 이름에 대한 금칙어 검사도 제거
  - 운영 DB에 이미 저장된 이름은 SQL로 기본값(`'친구'`)으로 일괄 변경

    ```sql
    update public.guestbook set author = '친구' where author <> '친구';
    ```

- **검증**: Supabase 클라이언트를 가짜 객체로 바꿔, DB로 실제 전송되는 데이터를 비교

  | | DB로 보내는 데이터 | DB에서 불러오는 항목 |
  | --- | --- | --- |
  | 수정 전 | `author`, `badge`, `message` | `id, author, badge, message, created_at` |
  | 수정 후 | `badge`, `message` | `id, badge, message, created_at` |

- **교훈**: “화면에 안 보인다”와 “수집하지 않는다”는 다릅니다. 개인정보 보호는 **저장과 전송 단계**까지 확인해야 합니다.

## TS-06. 포토카드 캐릭터가 세로로 늘어나 보임

- **증상**: iPhone에서 포토카드를 저장해 보니, 캐릭터들이 전반적으로 세로로 길게 늘어나 보임
- **원인**: 정사각형(220×220) 캐릭터 이미지를 가로 106, 세로 150인 영역에 맞춰 그려, 세로로 약 1.4배 늘어남

  ```js
  ctx.drawImage(img, x, y, 106, 150); // 가로세로 비율이 다름
  ```

- **해결** (`3b6bb5d`): 정사각형 비율을 유지해 그리고, 발끝 위치를 기준으로 배치

  ```js
  ctx.drawImage(img, -c.size / 2, -c.size * FOOT_RATIO, c.size, c.size);
  ```

  - 같은 PR에서 사용자 피드백을 반영해 단체 사진 구도와 고민 맞춤형 문구로 포토카드를 다시 설계
- **검증**: 데스크톱 Chrome에서 3개 경로와 여러 이름 길이로 생성 확인, iPhone Safari에서 생성 확인
- **교훈**: 이미지를 다른 크기로 그릴 때는 원본의 가로세로 비율을 유지해야 합니다.

## TS-07. 배경 음악이 들리지 않고 효과음만 들림

- **증상**: 이어폰으로 플레이했는데 효과음만 들리고, 배경 음악이 없는 것처럼 느껴짐
- **분석**
  1. 문서와 코드를 확인하니 통기타 아르페지오 배경 음악과 모닥불 소리가 구현되어 있었음
  2. 데스크톱 Chrome에서 오디오 출력 신호를 측정한 결과, 배경 음악이 재생되고 신호도 나오고 있었음. 즉 “재생되지 않는” 것이 아니라 “들리지 않는” 문제
  3. 첫 측정 한 번은 배경 음악이 정지 상태였으나, 이후 반복 측정에서는 재현되지 않음. 오디오 초기화 코드가 오류를 조용히 무시하고 있어 원인을 확인할 수 없었음
- **원인**
  - 배경 음악이 저음 위주(최저 87Hz)였음. 휴대폰 스피커는 이 대역을 거의 재생하지 못함
  - 배경 음악(-14dB)과 모닥불 소리(-24dB)가 효과음보다 작아, 기기 음량을 낮추면 묻힘
- **해결** (`ed04558`)

  | 항목 | 이전 | 변경 |
  | --- | --- | --- |
  | 배경 음악 음역 | 최저음 F2 (87Hz) | 한 옥타브 위 F3 (175Hz) |
  | 배경 음악 음량 | -14dB | -11dB |
  | 모닥불 소리 | -24dB | -18dB |
  | 오디오 오류 처리 | 조용히 무시 | `console.warn`으로 기록 |

  - 처음에는 -8dB로 올렸으나 효과음만큼 커져 배경으로 깔리는 느낌이 줄어, -11dB로 조정
- **검증**: 데스크톱 Chrome에서 재생 상태와 출력 신호 확인, iPhone에서 Vercel Preview를 직접 들어 보고 확인
- **교훈**: 소리는 측정값만으로 판단할 수 없고, 실제 사용자가 쓰는 기기로 들어 봐야 합니다. 그리고 실패를 조용히 무시하는 코드는 원인 추적을 막습니다.
