## TS-01. 캐릭터가 거대해지고 서로 겹침

- **증상**: 오두막 장면에서 흰색 족제비가 비정상적으로 크게 표시되고, 캐릭터들이 서로 겹쳐 가려짐
- **원인**: AI가 Tailwind CSS에 존재하지 않는 크기 클래스(`w-25`, `w-26`, `w-30`)를 생성했습니다. 이 클래스는 아무 스타일도 적용하지 않기 때문에, 크기 제한이 사라진 SVG가 영역을 가득 채웠습니다.
- **해결**
  - 모든 캐릭터 크기를 Tailwind 표준 클래스(`w-20 h-20 sm:w-24 sm:h-24`)로 통일
  - 방석 위에 앉아 있는 배치로 바꾸고, 캐릭터 간 간격을 고정
- **검증**: 수정된 화면을 직접 실행해 확인

## TS-02. 방명록 저장 실패

- **증상**: 방명록을 작성하면 “서버 저장 중 오류가 발생했어요. 테이블 설정을 확인해주세요.”라는 메시지가 뜨고 저장되지 않음
- **1차 조치 (해결되지 않음)**
  - AI는 `guestbook` 테이블이 이전 버전으로 남아 있거나 RLS의 INSERT 정책이 빠졌을 가능성을 진단했습니다. 테이블 생성 때 `ERROR: 42P07: relation "guestbook" already exists`가 발생했기 때문입니다.
  - 테이블을 다시 만들고 RLS 정책과 권한을 재설정하는 SQL을 실행했지만, 같은 오류가 반복됐습니다.
- **원인**: Supabase URL이 `https://<project>.supabase.co/rest/v1/`로 설정되어 있었습니다. Supabase JS 클라이언트는 기본 URL 뒤에 API 경로를 스스로 붙이므로, 기본 URL만 넣어야 합니다.
- **원인 파악이 늦어진 이유**: 오류 메시지가 실제 DB 오류를 가리고 “테이블 설정을 확인하라”고만 안내해, 테이블과 권한 쪽을 먼저 의심하게 됐습니다.
- **해결** (`f283ff8`)

  ```diff
  - url: "https://<project>.supabase.co/rest/v1/",
  + url: "https://<project>.supabase.co",
  ```

  ```diff
  - throw new Error("서버 저장 중 오류가 발생했어요. 테이블 설정을 확인해주세요.");
  + throw new Error(`DB 저장 오류 (${error.code || "ERR"}): ${error.message}`);
  ```

  - 오류 코드와 사유가 화면에 그대로 보이도록 바꿔, 이후 문제가 생기면 원인을 바로 알 수 있게 함
  - 등록에 성공하면 클라우드 목록을 바로 다시 불러와 화면에 반영
  - 1차 조치에서 정비한 테이블·RLS 구성은 현재 운영 스키마로 유지 ([supabase/schema.sql](../supabase/schema.sql))
- **검증**: 팬 사이트 공유 후 실제 사용자 2명의 방명록 저장 확인

## TS-03. 방명록에 글이 등록되면 기본 메시지가 사라짐

- **증상**: 방명록에 실제 글이 하나라도 등록되면, 캐릭터들이 남긴 기본 응원 메시지가 모두 사라짐
- **원인**: DB에 글이 있으면 DB 글만, 없으면 기본 메시지만 보여주는 양자택일 로직
- **해결** (`3761585`)

  ```diff
  - this.entries = mapped.length > 0 ? mapped : [...this.seedEntries];
  + this.entries = [...mapped, ...this.seedEntries];
  ```

  - 방문자 글은 최신순으로 쌓이고, 기본 메시지는 항상 맨 아래에 남도록 변경
  - 이후 기본 메시지를 6종 캐릭터 모두의 메시지로 확장(`cf7e9c1`)
- **검증**: 글을 등록한 뒤 기본 메시지가 함께 표시되는지 확인

## TS-04. iPhone Safari에서 포토카드 캐릭터가 표시되지 않음

- **증상**: 엔딩에서 응원 포토카드를 저장하면 배경과 문구만 나오고 캐릭터 6종이 보이지 않음 (iPhone Safari)
- **원인**
  - 캐릭터 SVG는 페이지에 한 번만 정의된 크레용 필터(`#crayonBrush`)와 볼터치 그라데이션을 `url(#...)`로 참조합니다.
  - 포토카드를 만들 때 SVG를 Blob 이미지로 분리하면, 그 이미지는 페이지에 접근할 수 없어 참조가 끊깁니다.
  - 끊긴 참조를 처리하는 방식이 브라우저마다 다릅니다.

  | 브라우저 | 끊긴 필터 참조 처리 | 결과 |
  | --- | --- | --- |
  | Chrome | 필터를 무시하고 그림 | 캐릭터는 보이지만 질감과 볼터치가 빠짐 |
  | Safari | 해당 요소를 그리지 않음 | 캐릭터 전체가 사라짐 |

- **분석 과정**
  1. 코드를 읽고 “필터 참조가 끊긴다”는 가설을 세움
  2. 수정 전 코드를 데스크톱 Chrome에서 재현해 보니 **캐릭터가 정상적으로 보임**. 가설과 다른 결과
  3. 같은 결함이 브라우저별로 다르게 나타날 수 있다고 보고, 발견 환경(iPhone Safari)을 확인
  4. 수정본을 Vercel Preview에 배포해 iPhone Safari에서 검증
- **해결** (`c725d90`): 페이지 공용 `<defs>`를 각 캐릭터 SVG 안에 복사해, 다른 문서에 의존하지 않는 SVG로 만든 뒤 이미지로 변환

  ```js
  function serializeCharSVG(id) {
    const sharedDefs = document.getElementById("sharedSvgDefs").outerHTML;
    return getCharSVG(id, { extraClass: "" })
      .replace('class="w-full h-full svg-char "', 'width="220" height="220" xmlns="http://www.w3.org/2000/svg"')
      .replace(/<svg[^>]*>/, (openTag) => openTag + sharedDefs);
  }
  ```

- **검증**

  | 환경 | 수정 전 | 수정 후 |
  | --- | --- | --- |
  | 데스크톱 Chrome | 캐릭터 표시, 질감·볼터치 누락 | 정상 |
  | iPhone Safari (Vercel Preview) | 캐릭터 미표시 | 정상 |

- **교훈**: 개발 환경(데스크톱 Chrome)에서 정상이어도 실제 사용 환경(모바일 Safari)에서는 다를 수 있습니다. 결함은 **발견된 환경에서 재현하고 검증**해야 합니다.
